## 4. 每 case 关键证据

每 case 独立 `robot_id = clear_estop_e2e_<pid>_<seq>` + 独立 tempdir +
独立 latch primary/.bak + 独立 loopback port。daemon stdout 走 JSON 模式
（`ROBOT_LOG_FORMAT=json`），harness 按行 capture。

### 4.1 `selftest`

仅 readiness probe（dry_run=true maintainer 轮询到 Ok）+ tear-down。

```
[gateway/stdout] ... "message":"ClearEStop ok",
  "request_id":"019dd266-5bb7-7fa9-9093-a10052aa8094",
  "idempotency_key":"ready_attempt_1","cleared_at_ns":473925019361491,
  "dry_run":true,"role":"maintainer","source":"clear_estop_e2e",
  "audit_reason":"clear_estop_e2e selftest readiness probe"
[daemon/stdout] ... "message":"final estop_latched persisted","latched":true
========== [all] case=selftest PASS ==========
```

selftest 不调真路径；latch 仍 latched=true（preset 1 不动）。

### 4.2 `reject_viewer`

viewer fake token + dry_run=false → tonic `PermissionDenied`；latch 不动。

```
# readiness probe（maintainer + dry_run=true）先过：
[gateway/stdout] ... "message":"ClearEStop ok","role":"maintainer",
  "audit_reason":"clear_estop_e2e selftest readiness probe"

# viewer denied（gateway authz 在调 daemon 前拒）：
[gateway/stdout] ... "level":"WARN","message":"ClearEStop denied: role lacks
  `clear_estop` capability","request_id":"019dd266-5c89-7eea-8562-7480768e5dbb",
  "role":"viewer"

# daemon final latch 仍 latched=true（**没**有 wire request 出门）：
[daemon/stdout] ... "message":"final estop_latched persisted","latched":true
========== [all] case=reject_viewer PASS ==========
```

harness body 同时断言 `latch primary+.bak` 仍 `1\n`（PASS = 断言通过）。

### 4.3 `happy_dry_run`

maintainer + dry_run=true → daemon `evaluate_clear_estop_dry_run`（read-only）
→ Ack(dry_run=true, cleared_at_ns>0)；latch 不动。

```
# readiness probe 先过（同 4.1/4.2）：
[gateway/stdout] ... ClearEStop ok ... idempotency_key="ready_attempt_1"

# 真 dry_run 调用：
[gateway/stdout] ... "message":"ClearEStop ok",
  "request_id":"019dd266-5d5b-7eab-ae9b-4995649f1562",
  "idempotency_key":"happy_dry_run_idem_1","cleared_at_ns":473925438741666,
  "dry_run":true,"role":"maintainer",
  "audit_reason":"clear_estop_e2e happy_dry_run"

# daemon final latch 仍 latched=true（dry_run 不写盘）：
[daemon/stdout] ... "message":"final estop_latched persisted","latched":true
========== [all] case=happy_dry_run PASS ==========
```

harness body 同时断言 `Ack.dry_run == true && cleared_at_ns > 0` +
latch primary+.bak 仍 `1\n`。

### 4.4 `happy_real`

maintainer + dry_run=false → daemon `try_apply_clear_estop`（三步硬序：
TorqueOffConfirmed gate → `save_estop_latch_clear` backup-first →
`clear_safety_latch` + flip guard）→ Ack(dry_run=false)；latch
primary+.bak **都**写 `0\n`。

```
# readiness probe 先过：
[gateway/stdout] ... ClearEStop ok ... "role":"maintainer",
  "audit_reason":"clear_estop_e2e selftest readiness probe"

# 真路径调用：
[gateway/stdout] ... "message":"ClearEStop ok",
  "request_id":"019dd266-5e2d-79be-a220-dc70a4d2c2c3",
  "idempotency_key":"happy_real_idem_1","cleared_at_ns":473925663914788,
  "dry_run":false,"role":"maintainer",
  "audit_reason":"clear_estop_e2e happy_real"

# daemon final latch 已写 latched=false（真路径生效）：
[daemon/stdout] ... "message":"final estop_latched persisted","latched":false
========== [all] case=happy_real PASS ==========
```

**关键不变量**（reviewer 拍板）：harness `read_latch_pair()` 断言
`primary == "0" && bak == "0"`，case PASS 隐含两份 latch 文件**都**存在
且都为 `0\n` —— `save_estop_latch_clear` backup-first 写 false 后两份
都存在，**不**是"删除"。

### 4.5 `idem_replay`

maintainer + 同 `idempotency_key` 调两次 dry_run=false → 第二次走 cache
Replay 路径返**同一** cached `cleared_at_ns`；latch 真 fsync 只发生一次。

```
# readiness probe 先过：
[gateway/stdout] ... ClearEStop ok ... "audit_reason":"... readiness probe"

# 第一次（FreshInsert 路径，调 daemon → save_estop_latch_clear）：
[gateway/stdout] ... "message":"ClearEStop ok",
  "request_id":"019dd266-5f00-79e0-b357-3bb597b58e60",
  "idempotency_key":"idem_replay_idem_1",
  "cleared_at_ns":473925874708650,
  "dry_run":false,"role":"maintainer",
  "audit_reason":"clear_estop_e2e idem_replay"

# 第二次（同 idem_key + 同 fingerprint → handler Step 5 走 Replay 分支）：
[gateway/stdout] ... "message":"ClearEStop idempotency replay",
  "request_id":"019dd266-5f11-7654-8243-e4e3fde933f5",   ← 不同 request_id
  "idempotency_key":"idem_replay_idem_1",                  ← 同 idem_key
  "cleared_at_ns":473925874708650,                         ← **同** cleared_at_ns
  "dry_run":false

# daemon final latch latched=false（real fsync 只发生一次）：
[daemon/stdout] ... "message":"final estop_latched persisted","latched":false
========== [all] case=idem_replay PASS ==========
```

**关键证据**：

1. `cleared_at_ns` 严格相等（`473925874708650 == 473925874708650`）。如
   果第二次走的是 FreshInsert 而不是 Replay，daemon 端会再调一次
   `clock.now()`，cleared_at_ns 必然不同。
2. gateway 第二次的 trace 行 message = `"ClearEStop idempotency replay"`
   （handler `Step 5: cache.decide` 的 `Decision::Replay` 分支专属
   tracing；详 `crates/robot-rpc/src/gateway.rs` Step 5）。harness
   `wait_for_marker` 扫 500ms 超时即 fail。
3. harness body 在两次调用之间断言 `latch primary+.bak == "0"` —— 第二
   次调用后再次断言**仍** `"0"`（real fsync 不重复发生）。
