### 1.4 v0.4 留下的对外契约（v0.5 必须保持向后兼容）

- **`ActionKind` enum 三层同步**：proto `ActionKindProto` / fbs
  `ActionKindFb` / lib `ActionKind` 三层 + 三个 variant count 锁测
  同步（候选 1 / 2 round 2 atomic land 同款模式；新 variant 加在
  4 之后续号）。
- **`source_task_id == ctx.command_seq` 单调契约**（B3 §3.7 + 候选 1
  + 候选 2 round 2 沿用）：S1 `TickState.cmd_seq` 单一 source；
  新 backend 必须沿 `build_hold_command(_, _, _, ctx.command_seq, _)`
  路径，**不**得引入 backend 私有 counter。
- **`ActionContext` 字段集只加不减**：候选 2 round 2 引入 `solver:
  Option<&dyn ArmIkSolver>` 字段；未来扩 backend 如需新 ctx 字段沿同

- **3 类 `ActionStartError` 映射严格分离**（候选 2 round 2 §3.2 锁定）：
  `PayloadDecode`（fbs verify fail）/ `HardwareMismatch`（solver
  joint_count 错）/ `Rejected`（其它语义错 含 IkError 全 5 variant）；
  3 类全部 → tonic `Code::FailedPrecondition`（沿 wire.rs:340）。
- **operator workflow 现状空白**：v0.4 land 6 RPC 真起，但 maintainer
  / operator 跑命令的入口（CLI / web / 脚本）尚未沉淀；这是 v0.5
  第一优先级（详 §2.1）。
- **dimos-deploy 端 0 行 gRPC client 代码**：候选 4 light Research
  锁定的现状基线（详 [`v0.4_dimos_research.md`](v0.4_dimos_research.md)
  §2.2）；v0.5 不擅自跨仓改 dimos-deploy。
- **`cargo deny check` baseline FAILED 沿用**：3 处既有 license
  reject / parse warning（`assert_no_alloc` BSD-1-Clause +
  `serialport` MPL-2.0 + `unescaper` GPL-3.0/MIT）沿 round 1 + 候选 1
