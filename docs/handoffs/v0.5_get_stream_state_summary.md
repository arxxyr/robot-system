## 4. 一条非安全保证（read auth，C1 延续）

- **C1 延续（⚠ 非安全保证）**：`GetStateRequest` / `StreamRequest` **不含 auth /
  token 字段**；服务端 **不读、不校验**任何 metadata token。**无 token 与任意
  token 结果完全一致**（AC-6 e2e 实测两路同结果）。**不得**据此认为 read RPC 已
  鉴权；`read_state` cap（design §5.4）**本版不实现该安全属性**；后续 metadata
  auth 是独立候选 / round。

## 6. 工程经验（接班 / 复用要点）

- **gateway-only e2e**：state RPC 读 gateway 自己的常驻 state 池（D4），池订阅
  `/<robot_id>/s0/<hardware_id>/state` 上 `FakeStatePublisher` 喂的 `JointState`
  ——**不经 s1**（s1 是 coordinator，不持权威硬件 state）。故 `state_rpc_e2e` 只起
  **gateway（带 `--config`）+ N 个 FakeStatePublisher**，比 `task_rpc_e2e` 轻；
  readiness 走 gateway marker + connect + `GetState(NEVER)→NotFound`（不依赖
  publisher 首帧时机 / 不需 s1 RR server）。
- **release-first 二进制解析**：`locate_test_bin`（沿 task_rpc_e2e）**优先
  `target/release/`**。改了 gateway 后**必须 `cargo build --release` 刷新
  release 二进制**，否则 e2e 用到 stale release gateway（症状：gateway 退出码 2 +
  打印旧 help）。CI / 完结 gate 顺序 = `cargo build --release --workspace` →
  `cargo test --workspace`。
- **节流判据 timing 敏感**：`stream_state_*` 测 **client 端逐帧到达间隔**；服务端
  `tokio::time::interval` 保证发送间隔 ≥ period（故 `帧数 ≤ ⌈window/interval⌉+1`
  是**硬上限**，client 负载无法突破），但相邻间隔的 client 实测在极端 starvation
  下理论可压缩。本轮隔离 + workspace 并发两路均过；若 reviewer 遇 flake，隔离
  `--test-threads=1` 跑 `state_rpc_e2e` 为确定性证据。
- **convert-on-read**：cache 存 owned `JointState` body bytes（`view.body.raw()
  .to_vec()`），读路径才 `flatbuffers::root` + `state_convert`（省高频 publish
  rate 上的转换）；`StateLookup` 三态直接对应 D9 错误码。
