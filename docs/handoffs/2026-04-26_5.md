## 2. reviewer round 4 否决 + 修复

### 2.1 阻断 1（高 / `docs/00_design.md:1134` §6.7 #2 实施）

**reviewer 复核证据**：
> systemctl kill -9 daemon → Restart=on-failure 只能证明进程死亡后会被
> 拉起，不证明 WatchdogSec 能监控 S0 内部卡死。当前
> `crates/robot-s0/src/systemd_notify.rs:100` 是独立线程无条件
> WATCHDOG=1，只要这个线程还活，RT/SerialRT/ipc/pub 卡死也会继续喂
> systemd。

**修复**（commit `4222df5` + `e15cd41`）：
- `systemd_notify` 加 `LivenessObserver { label, tick: Box<dyn Fn() -> u64> }`
  + `LivenessObserver::from_atomic(label, Arc<AtomicU64>)` /
  `from_fn(label, F)` 两个构造方法
- `spawn_watchdog_thread` 接受 `Vec<LivenessObserver>`：每周期对所有
  observer 调 `tick` 闭包 + 跟上次 snapshot 比较；**任一**停滞就**不**
  发 `sd_notify(WATCHDOG=1)`，systemd `WatchdogSec` 超时 →
  `Restart=on-failure` 拉起。
- 启动 grace 一周期让 worker 完成 first tick，避免误报。
- `s0_daemon` main 把 4 worker (`ipc_thread` / `rt_thread` 或
  `serial_io_thread` / `pub_thread` / `io_thread`) 的 `tick_count`
  收集成 observer 传给 watchdog。
- `ExecutorHandle::make_tick_observer` 给 HardRt / SerialRt 两路
  分发出对应的 observer。
- **commit `e15cd41` 二次修**：watchdog loop 序列从"snapshot prev → loop
  { compare → sleep }" 修成"snapshot prev → loop { sleep → compare }"，
  避免第一次 iteration 0 时间过去导致误报 stalled。

**锁测**：
- `watchdog_pings_when_all_observers_alive`（持续 tick → ≥3 ping 到
  达 NOTIFY_SOCKET）
- `watchdog_withholds_ping_when_observer_stalled`（permanent stall →
  恰 1 grace ping，之后 enforce 阻止）

**真机回归（Orin happy path 8s）**：
- Daemon active + `state=Ready` 持续
- **0 stalled warning**（修 loop 序列前是 4 false positive；现在 0）
- 8s 后 main PID 不变 → systemd 没误重启
- crash_restart_smoke 5/5 PASS（端到端 SIGKILL daemon → systemd 重启
  → latch=true persistence）

### 2.2 阻断 2（高 / `docs/00_design.md` §6.7 #3 实施）

**reviewer 复核证据**：
> crash_restart_smoke 5/5 PASS 只证明"EStop 后 SIGKILL，latch 已落盘
> 且重启读回 true"。它不证明"只能 ClearEStop 清除"。当前
> `crates/robot-s0/src/estop_latch.rs:88` 在 primary + bak 都不存在时
> 返回 false，这和 §6.7 "只能 ClearEStop RPC 解除 / 读不到拒绝 READY"
> 冲突。

**修复**（commit `4222df5`）：
- `estop_latch` 加 `MissingLatchPolicy` enum：
  - `Strict`（生产默认）：primary + backup 都不存在 → 返
    `io::ErrorKind::NotFound`，daemon 启动期拒启动 + tracing::error 报
    "需 `--allow-empty-latch` opt-in 或 `ClearEStop` RPC（v0.3）解除"。
  - `AllowEmpty`：保留旧 `Ok(false)` 行为（首次部署 / bring-up / 单测）。
- `load_estop_latch_with_mode(path, mode)` 显式入参版本，原
  `load_estop_latch(path)` 封装走 `Strict`（生产 daemon 默认）。
- `s0_daemon` 加 `--allow-empty-latch` CLI flag（default false）。
- `crash_restart_smoke` 调 daemon 时加 `--allow-empty-latch`（test 场景
  每次清空 latch 目录，需要 opt-in）。
- 单测：
  - `load_nonexistent_strict_returns_not_found_err`（钉死 fail-closed +
    err msg 含 `--allow-empty-latch` hint）
  - `load_nonexistent_allow_empty_returns_false`（保留旧行为）
  - `load_returns_not_found_when_both_missing_strict`（替换旧
    `_both_missing` 测试，钉死 strict 行为）

**真机回归**：
- 不带 flag 启动 → daemon ERROR `"primary AND backup both missing;
  fail-closed (need --allow-empty-latch opt-in or ClearEStop RPC in v0.3)"`，
  systemd unit 进 `failed`。
- 带 `--allow-empty-latch`（systemd unit drop-in override）→ unit
  `active` + state=Ready。

**v0.3 完整闭环留白**：v0.2 没 `ClearEStop` RPC，本修复用 CLI flag
opt-in 守门 "rm latch && restart"，但**不**等价于"只能 ClearEStop
解除"完整语义。v0.3 RPC 落地后：
- 删 `--allow-empty-latch` flag
- 默认 strict 仍 fail-closed；只有 `ClearEStop` RPC（带 maintainer auth）
  才能 clear latch（写 `0\n` 进 primary + bak）
- 那时才能宣称 §6.7 #3 完整满足
