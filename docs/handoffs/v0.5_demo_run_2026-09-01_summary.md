## 3. FAIL 事件取证（4L-①）与发现

### 时间线（CST）

- 10:54 三路相机直播启动（RealSense@Bus02 + 两 USB2 webcam@**Bus01，与两臂
  串口同 480M 控制器同 hub**）。
- 10:54→11:24 直播运行 30 min：两 S0 以 200 Hz 轮询，**零超时**。
- 11:24:0x `SetEnabled(true)` 左 → RPC 返 `AdapterError`；心跳序列
  `Safe(estop=false)` → 11:24:03 `Safe(estop=true)`，**从未采样到
  Enabled/Fault**（亚 2 s 内闭合）；finalizer EStop 弱 Ack 成功，左 latch
  回写 `1\n`。
- 11:24:03.17 全 boot **唯一**一次 `TransportTimeout`：`read_state
  Present_Velocity` 等满 1 s **收 0 字节**（整 bus 静默）。
- adapter enable 路径**零日志**（无 `sync_goal_to_present failed`、无
  `torque_enable write retry`）。
- 停相机 → 重清 latch → 重测：通过；此后左右/双臂/夹爪四个上扭 phase
  全过、全程零超时。

### 判定链（代码排除法）

**当前证据最吻合的候选路径**（codex round 1 收窄：非"唯一"）=
`ipc_tick.rs` Step 2 头部的 **`PENDING_TOTAL_TIMEOUT = 1 s` 总超时分支**
（`commit_fault` 前后无任何 tracing）：enable 的 adapter ack 未在 1 s
内决议 → ipc 先行 Fault → RPC `AdapterError` → bin finalizer EStop。
**不能排除的其他入径**：`AdapterResp::Err` / `SafetyLatched` /
`Unsupported` 等同样落 `Fault(AdapterErr)`（其中部分带日志但可能未被
采到）；且 11:24:03.17 的唯一 `TransportTimeout` 时间上落在 finalizer
EStop 附近，**不能直接定为首次 enable 失败的因**（也可能是 Fault 后
串口线程继续动作期间的伴生现象）。F1 的预算倒挂为算术结论，
不依赖本归因，仍成立。

### 归因（如实陈述，不下定论）

A/B 混淆：FAIL 那次同时是①相机开启、②四个月闲置后的首次上扭。此后证据：
右 bus **首次上扭**（相机关）一把过 → 削弱"首次上扭瞬态"假说；但 30 min
直播期间轮询零超时 → 相机稳态带宽不构成干扰，**若是相机，机制只能是
enable 多包事务窗口内的瞬时调度冲突**（同 hub 等时流 vs CDC-ACM bulk）。
两假说（相机 hub 竞争 / 上扭瞬时电流拉低供电）各余 n=1，未定论；demo
后续全程关相机执行，未再复现。

- extlinux APPEND += `isolcpus=4,5 nohz_full=4,5 rcu_nocbs=4,5`（备份
  `/boot/extlinux/extlinux.conf.bak-20260901`）；重启后实证
  `/proc/cmdline` 含参 + `/sys/devices/system/cpu/isolated` = 4-5。
- **内核 `# CONFIG_NO_HZ_FULL is not set`** → `nohz_full` / `rcu_nocbs`
  被内核静默忽略，实际生效的只有 isolcpus 本体（调度器级隔离；tick 中断
  仍在隔离核上）。如实登记，不高估。
- systemd `[Manager] CPUAffinity=0-3`（PID1 亲和实证 0-3）；xHCI usb1
  IRQ 124 掩码 → 0f + `robot-irq-affinity.service` oneshot enabled
  （重启后 Result=success，IRQ 号未漂）。

### 7.4 重启附带事件与运维发现

- **DHCP IP 漂移**：重启后 10.0.1.41 → 10.0.1.40（watcher 盯旧 IP 空转，
  由用户告知新址）。
- **旧栈开机自启**：coordinator + web 系 enabled，重启即自启占串口——
  demo 期间全靠人工 stop 掩盖。用户拍板 disable（见 §5）。
- **F8（运维项）**：以 root 跑任何 iceoryx2 程序（本次 = sudo 跑
  baseline）会创建 root 属主 `/tmp/iceoryx2/`（750）与
  `/dev/shm/iox2_*_global_mgmt`（700），此后**所有非 root iceoryx2 进程
  结点创建裸报 `InternalError`**（IOX2_LOG_LEVEL=trace 亦无路径细节，
  可诊断性差）。s0 首启连崩 5 次即此因（崩点在 guard exec 之后，连败
  预算不受影响，成功后计数回 0）。处置：栈停时
  `sudo rm -rf /tmp/iceoryx2 /dev/shm/iox2_*`；教训：baseline 不再
  sudo 跑（改为给用户 rtprio rlimit），或 root 跑完立刻清理。
