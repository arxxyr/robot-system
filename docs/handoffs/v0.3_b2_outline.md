### 2.2 ActionKind

**reviewer 拍板（2026-04-28）**：B2 enum 仅 2 个 variant；不放 `Stop`；
不放 B3 占位。

```rust

    /// B2 mock：dwell N ms 后完成；不输出新 JointCommand。
    DwellMs,
    /// B2 mock 占位：保持当前 anchor，等价 IDLE 但走 EXECUTING 路径。
    HoldPose,
```

**为什么撤 `Stop`**（reviewer 阻断 3 修正）：
`Stop` 边界混淆了 4 个不同语义层 —— task cancel（撤 in-flight action） /

**为什么撤 B3 占位**：B2 测试不需要"无对应 backend → 拒绝"路径来锁定

查表本身覆盖；占位 variant 反而引诱误用 + 提前固化未拍板形状）。B3 land
对应 backend 时再加 enum variant，向 §6.6.4 errata 边界对齐。

### 2.4 ActionBackend trait

```rust
pub trait ActionBackend: Send + Sync {
    /// 跟 inventory 注册名一致（profile [s1.profile.backends] 选）。
    fn name(&self) -> &str;
    fn supported_kinds(&self) -> &[ActionKind];
    fn supported_schemas(&self) -> &[u32];

    fn start(
        &self,
        req: &ActionRequest,
        ctx: &ActionContext,
    ) -> Result<Box<dyn ActionInstance>, ActionStartError>;
}

pub trait ActionInstance: Send {
    /// 50 Hz tick；backend 决定本 tick 是否产生新 JointCommand。
    fn tick(&mut self, ctx: &mut ActionContext) -> Result<ActionTickOutput, ActionFailure>;
    /// Cooperative cancel：set flag → 下一次 tick 返
    /// `Completed(PartialSuccess)` 或 `Failed(...)`。
    fn cancel(&mut self, ctx: &mut ActionContext) -> Result<(), ActionCancelError>;
}

pub enum ActionTickOutput {
    /// 还在跑；可选附本 tick JointCommand body bytes（None = 沿用上次 /
    /// hold 输出，详 §6 共存策略）。
    Continue { progress: f32, command: Option<JointCommandBody> },
    /// 完成；coordinator 转回 IDLE，恢复 hold loop。
    Completed(ActionOutcome),
}

/// reviewer 决策 #8：backend `tick()` 返 newtype 包 raw bytes（不直接裸
/// `Vec<u8>`），让"这是 JointCommand body 字节流"在类型上一目了然，
/// 也防 backend 误把任意 bytes 塞进来。
#[derive(Debug, Clone)]
pub struct JointCommandBody(pub Vec<u8>);

pub enum ActionOutcome {
    Success,
    PartialSuccess { warning: String },  // 例：trajectory clamped to limits
}

pub enum ActionFailure {
    DeadlineExceeded,
    PreconditionFailed(String),
    AdapterError(String),
    SafetyAbort(String),
    InternalError(String),
}
```

## 3. policy ↔ action 边界（B2 不接 policy host）

§4.7 / §4.8 现存 `Policy` trait（`step(obs, deadline) → Action`）+
InProcess / External PolicyHost 是**数据流抽象**：observation → action
chunk。B2 outline 引入的 `ActionRequest` 是**控制流抽象**：external goal
→ backend execution。

| 维度 | Policy | Action (B2) |
|---|---|---|
| 抽象层 | 数据流（obs → action） | 控制流（goal → execution） |
| 输入 | sensor observation 流 | RPC `InvokeTask` / 内部 scheduler |
| 输出 | `ActionChunk`（关节目标流） | `JointCommand` body bytes |
| 住哪里 | `robot-policy-host` / `robot-s1::policy_host/` | `robot-s1::action_backend/` |
| B2 状态 | **不**接 | 引入 trait + mock backend |

**一个 action 可以调用 policy 作为它的实现**（B3 `PolicyAction` backend
= "consume policy /<robot>/policy/<name>/action_chunk topic"）。所以两
者不互斥，B2 的 `ActionKind::PolicyAction` 是占位，B3 落地时 backend
内部 subscribe action_chunk 然后产 `JointCommand` 给 coordinator。

## 5. S1 coordinator 状态机扩展

### 5.1 B1 现状（隐式 IDLE 单态）

```text
BOOTING ──[anchor success]──> IDLE ──[shutdown signal]──> SHUTTING_DOWN
                                ↑
                          hold loop forever
                          (50 Hz hb + 50 Hz hold cmd)
```

### 5.2 B2 目标

```text
BOOTING ──> IDLE ──[Coordinator::submit OK]──> EXECUTING
                                                  │
                                  ┌───────────────┼─────────────────┐
                                  ▼               ▼                 ▼
                  Completed(Success/PartialSuccess)  Failed(Pre…)   Failed(SafetyAbort/Adapter/Internal)
                                  │               │                 │
                                  ▼               ▼                 ▼
                                 IDLE            IDLE           DEGRADED
                                  │               │                 │
                                  ▼               ▼                 ▼
                          (hold loop 自动恢复)              (S1 内部 degraded：
                                                            **继续** B1 hold + heartbeat，
                                                            拒绝新 submit；**不**宣称 S0
                                                            CONTROL_LOST_STOP，详 §6.5 + §10
                                                            决策 #10 reviewer 拍板方案 d)

DEGRADED ──[B4 ClearError RPC]──> IDLE   (B2 仅 stub 内部 API，B4 接 wire)
任何状态 ──[SIGTERM/SIGINT]──> SHUTTING_DOWN
```

### 5.3 实现层（B2 落地范围）

- `enum CoordinatorState { Booting, Idle, Executing { action_id, started_at_ns }, Degraded { reason }, ShuttingDown }`
- `Coordinator::submit()` 内部用 `Mutex<CoordinatorState>` 守门：
  - `Idle` → `Executing` 允许
  - `Booting` / `Executing` / `Degraded` → 返 `SubmitError::*`
- tick loop 每帧按 state 分支：
  - `Booting`：B2 不出现（anchor 完即 Idle）
  - `Idle`：跑 B1 hold loop（hb + hold cmd）
  - `Executing`：调 backend.tick()；按 `ActionTickOutput` 转移
  - `Degraded`：**继续** B1 hold loop（hb + hold cmd），拒绝新 `submit()`（详 §6.5 + §10 决策 #10 reviewer 拍板方案 d）
  - `ShuttingDown`：break loop
- `clear_error()` 内部 API：`Degraded → Idle`，B2 仅声明 + 单测；B4 接 RPC。

**HOMING 状态保留 enum variant + 注释 "B2 不实现，沿 BOOTING → IDLE
直跳"**；v0.4+ 真接 home routine 时再实现。

## 6. 与 B1 hold loop 共存

**reviewer 拍板（2026-04-28）**：选项 A (override)。本节保留三选项
对比作决策来源审计；正文实现按选项 A。

### 6.1 选项 A — Override（拍板）

`Executing` 时 hold loop 停发 cmd，只发 hb；backend 全权控 cmd：

- backend `tick()` 返 `Continue { command: Some(body) }` → coordinator 立即 publish
- backend `tick()` 返 `Continue { command: None }` → coordinator 本 tick 不发 cmd（让 S0 沿用上一帧 cmd 直到 deadline_ns 过期）
- backend `tick()` 返 `Completed(...)` → coordinator 转 Idle，下一 tick 起 hold loop 自动接管
- backend `tick()` 返 `Failed(...)` → coordinator 转 Idle (PreconditionFailed) / Degraded (其余)

最少代码，边界清晰，跟 B1 (2/3) `tick_once` 干净对接。

### 6.2 选项 B — Fallback

`Executing` 时 hold loop 仍 50 Hz 发 cmd（target=anchor），但若 backend
本 tick 输出 `Some(body)` 则覆盖。Backend 隐式只决定 "差量更新"。

需要 coordinator 跟踪 backend 是否"沉默" + merge 策略；多一层 state。

### 6.3 选项 C — Source 抽象

抽出 `CommandSource` trait：`HoldSource` (target=bias) / `ActionSource`
(adapt over backend); coordinator 永远 `current_source.next_command()`。
最干净抽象但 B2 引入更多代码 + state 变迁。

### 6.4 拍板理由
- 最少 churn（B1 (2/3) `tick_once` 沿用，加一层 state-conditional dispatch
  即可）
- 安全默认：backend 失败立刻回 hold（last anchor），不发新 cmd 但 hb 仍 50
  Hz → S0 watchdog 不会误触发 CONTROL_LOST
- B3 真 backend 落地后若发现要 merge bias / clip rate 再升级 source 抽象

### 6.5 Action 失败时的 fallback

| 失败类型 | 转移 | 失败后 tick 行为 |
|---|---|---|
| `PreconditionFailed` | → IDLE | B1 hold（hb + hold cmd）自动恢复 |
| `DeadlineExceeded` | → IDLE | 同上 + 错误事件入 audit log |
| `SafetyAbort` | → DEGRADED | **继续** B1 hold（hb + hold cmd）；拒绝新 `submit`；等 `clear_error()` |
| `AdapterError` | → DEGRADED | 同 SafetyAbort |
| `InternalError` | → DEGRADED | 同 SafetyAbort |

**reviewer 阻断 2 修正**：B2 进 DEGRADED **不**宣称 S0 走
`CONTROL_LOST_STOP`。原因：S1 仍 50 Hz 发 hold cmd + 50 Hz 发 hb，
S0 看到的 `command/heartbeat` 永远不 stale，watchdog 不会触发
`CONTROL_LOST_*` 子态。所以 B2 DEGRADED 是**纯 S1 内部状态**：
S1 拒绝新 action / 走 `clear_error()` 路径恢复，**不**改变 S0 视角下
的输出 ABI。真正的 "safety stop / S0 进 control-lost" 语义留 B3 / B4
单独拍板（届时按 "是否 latch / 是否走 EStop / 是否绕 backend tick"
等具体行为定 wire 改动）。

## 7. 与 B4 robot-rpc full gateway 边界

B2 暴露的 in-process Rust API（**不**经 iceoryx2 / **不**经 tonic /
**不**链接 tokio —— 跟 `crates/robot-s1/src/lib.rs` 顶部 doc "Phase B
全程同步线程模型，对齐 mock_s1" 一致）：

```rust
impl Coordinator {
    pub fn submit(&self, req: ActionRequest) -> Result<ActionTicket, SubmitError>;
    pub fn cancel(&self, action_id: ActionId) -> Result<(), CancelError>;
    pub fn status(&self, action_id: ActionId) -> Option<ActionStatus>;
    /// B4 RPC ClearError 入口；B2 仅 stub。
    pub fn clear_error(&self) -> Result<(), ClearError>;
}

pub struct ActionTicket {
    pub action_id: ActionId,
    /// 同步事件接收端；coordinator tick loop 把 ActionEvent 推到 sender，
    /// 调用方在普通线程 try_recv / recv。**不**用 tokio。
    /// B4 时 robot-rpc-gateway 在它自己进程里用 tokio runtime + 一个
    /// adapter thread 把 std::sync::mpsc::Receiver 桥到
    /// tokio::sync::mpsc::Sender，然后接 tonic stream（adapter 模式跟
    /// A1 RR I/O thread 同款，跨 sync ↔ async 边界在 robot-rpc，不污染
    /// robot-s1）。
    pub events: std::sync::mpsc::Receiver<ActionEvent>,
}

pub enum ActionEvent {
    Started { at_ns: u64 },
    Progress { progress: f32, at_ns: u64 },
    Completed { outcome: ActionOutcome, at_ns: u64 },
    Failed { failure: ActionFailure, at_ns: u64 },
    Cancelled { at_ns: u64 },
}

pub enum ActionStatus {
    Pending,
    Executing { progress: f32 },
    Completed(ActionOutcome),
    Failed(ActionFailure),
    Cancelled,
}
```
