## 2. 改动清单（细节）

### 2.1 撤销 Stage 1 §5.1 "iceoryx2 multi-sub race"

| 文件 | 改动 |
|---|---|
| `crates/robot-transport/src/iceoryx2/qos.rs` | 加 `TopicClass::Heartbeat` (`max_subscribers=8`, `safe_overflow=true`, `history=4`, `buffer=4`)。`S1CmdVel` 保持 max=1 给真正 cmd_vel。`safe_overflow_semantics` 测试加 Heartbeat；新增 `observer_classes_support_multi_subscriber` + `heartbeat_is_drop_old` 两条 unit test |
| `crates/robot-transport/tests/iceoryx2_roundtrip.rs` | 加 `heartbeat_class_supports_two_subscribers_receiving_same_publish`（两个 sub 拿同一帧）+ `s1_cmdvel_class_rejects_second_subscriber`（反向证明 max=1 真的拒第二个 sub，不是恒真）|
| `crates/robot-s0/src/{pub_thread.rs, ipc_thread.rs, bin/s0_daemon.rs}` | hb pub/sub 都 `S1CmdVel` → `Heartbeat` |
| `crates/robot-s0/tests/serial_rt_e2e.rs` | 同上（pub + sub 都迁，否则 service QoS 不匹配 open 失败） |
| `crates/robot-cli/src/bin/robotctl.rs` | hb sub 迁 |
| `crates/robot-s1/src/bin/mock_s1.rs` | hb pub 迁 |
| `crates/robot-tests/src/bin/iceoryx2_rt_baseline.rs` | hb pub + sub 迁 |

**为什么必须全栈一致迁**：iceoryx2 service 由 (service_name, payload type,
QoS profile) 唯一确定。pub 在 service A、sub 用不同 QoS 试图 open 同一
service name → attribute mismatch / open 失败。所以哪怕只有一个进程要
新 class，**全部** pub/sub 一次性迁过去才能跑通。

**反向 sub 锁测的必要性**：原本 user 怀疑 "iceoryx2 0.8.1 静默吞 max
limit 不报错"。本 session 的 `s1_cmdvel_class_rejects_second_subscriber`
锁测证明 iceoryx2 0.8.1 在同 node 单进程场景下**会**对第二个 sub 返
错。这跟 Stage 1 真机观察 ("0 sample") 不完全对得上 —— 可能跨进程
（两个 robotctl）和单进程 (test 内) 的 max 守门路径不一样，但**结论一
致**：max=1 + 多个想订阅的人 = 不行。修复方案（max=8）让真机不会再撞这
条限制，下次 Stage 2 §4 顺手 2 个 watch 同跑就能回归。
