## 3. 关键契约审计：`ActionContext.command_seq == TickState.cmd_seq`

> **本节是 B3 最核心的设计取舍线索**；下一段 B4 做 RPC adapter / async
> bridge / event stream 时容易在上下文切换里丢掉"为什么不能 backend
> 私有 counter"的审计动机。本节给 B4 接班人提供完整 reasoning chain。

### 3.1 契约一句话

**HoldPose backend（及任何后续真 backend）产出的 `JointCommand` body
里的 `source_task_id` 字段，必须等于 `run_action_tick_loop` 当前
publish frame 的 `TickState.cmd_seq`；不得 backend 私有计数。**

### 3.2 阻断证据链（reviewer round 2 引）

| 文件:行 | 内容 | 推论 |
|---|---|---|
| `crates/robot-s1/src/coordinator.rs:342` | B1 hold loop 用 `state.cmd_seq` 作 `source_task_id`（`build_hold_command(.., source_task_id: state.cmd_seq, ..)`） | source_task_id 跟 publish frame seq 同源 |
| `crates/robot-s0/src/ipc_thread.rs:903` | `buf.seq = fb.source_task_id();` —— S0 把 fbs body 的 source_task_id 直接写成 `JointCommandBuf.seq`（**不**是 FrameHeader.seq） | S0 端的 seq 单调性绑定在 fbs source_task_id 上 |
| `crates/robot-core/src/adapter.rs:119-120` | `pub seq: u64` "命令 seq 号，单调递增；rt_thread 判 CONTROL_LOST → ACTIVE 恢复时用" | wire 协议契约：单调递增是硬要求，不是 audit 字段 |

### 3.3 私有 counter 反例（round 1 默认推进被打回）

如 backend 私有 counter 从 0 起增：
- daemon 先 Idle hold 跑 N 帧（source_task_id = 0..N）。
- 进入 EXECUTING（HoldPose 私有 counter 从 0 起 = 0..M）。
- S0 看到 source_task_id 序列 `..., N, 0`（**回退**）。
- 破坏 `adapter.rs` 单调契约。
- `rt_thread` 判 CONTROL_LOST → ACTIVE 恢复路径误触发风险。

### 3.4 round 2 拍板修法（已 land 在 `cc6b2df`）

**(i)** `ActionContext` 加 `command_seq: u64` 字段：
```rust
pub struct ActionContext<'a> {
    pub clock: &'a dyn RobotClock,
    pub layout_id: u64,
    pub hardware: &'a HardwareSection,
    pub config: &'a CoordinatorConfig,
    pub anchor_bias: &'a [f64],
    pub command_seq: u64,  // ← B3 round 2 加
}
```

**(ii)** `Coordinator::tick_action` 签名加 `command_seq: u64` 参数：
```rust
pub fn tick_action(
    &self,
    clock: &dyn RobotClock,
    command_seq: u64,  // ← B3 round 2 加
) -> Option<JointCommandBody>;
```

**(iii)** `run_action_tick_loop` 调用点（`coordinator.rs::865`）：
```rust
if let Some(body_struct) = coordinator.tick_action(clock, state.cmd_seq) {
//                                                        ^^^^^^^^^^^^^
//                                                        透传当前 publish frame seq
    publish_body::<markers::JointCommand, _>(
        cmd_pub, body_struct.as_bytes(),
        state.cmd_seq,  // FrameHeader.seq 也用同源
        cfg.source_id, now_ns,
    )?;
    // ...
    state.cmd_seq = state.cmd_seq.wrapping_add(1);
}
```

**(iv)** HoldPose backend tick 直接复用：
```rust
let body = build_hold_command(
    ctx.config,
    ctx.layout_id,
    ctx.anchor_bias,
    ctx.command_seq,        // ← 透传上来的 seq
    ctx.clock.now().0,
);
```

### 3.5 为什么 submit / cancel 路径用 `command_seq: 0`

`Coordinator::submit` 里构造 ActionContext 给 `backend.start` 调用；
`Coordinator::cancel` 里构造 ActionContext 给 `backend.cancel` 调用。
这两路径**不**在 publish frame seq 流上：
- `backend.start` 通常返 `ActionInstance`，不产 body bytes。
- `backend.cancel` 通常仅 set flag 不产 body bytes。

如某 backend 的 `start` / `cancel` 真要产 body（例如 v0.4 引入 RT
emergency path），必须 reviewer 单独拍板新设计；当前 `command_seq: 0`
哨兵符合 B2/B3 全部 backend 的契约。

### 3.6 测试锁住的层次

| 层 | 测试 | 所在文件 |
|---|---|---|
| backend tick 字节级（独立） | `tick_returns_continue_with_some_hold_body_bytes_bit_equivalent_to_build_hold_command` | `hold_pose.rs::tests` |
| 单 loop call 内同源（happy） | `happy_hold_pose_publishes_hold_cmd_bit_equivalent_through_override` | `tests/action_dispatch.rs` |
| **跨段单调（cross-segment）** | `cancel_hold_pose_during_executing_emits_cancelled_then_idle_resumes_hold` | `tests/action_dispatch.rs` |
| wire 回归（双路 smoke） | `crash_restart_smoke --iterations 5` 默认 + `--use-mock-s1` | `release` smoke |

### 3.7 B4 接班人注意事项

B4 起 robot-rpc gateway 接 tonic + adapter thread 把
`std::sync::mpsc::Receiver<ActionEvent>` 桥到 `tokio::sync::mpsc`：
- **不**在 adapter thread 里改 `source_task_id` / 重写 frame header
  seq —— wire 已经从 S1 publish 出去之后，gateway 仅消费 event 流。
- B4 加 `InvokeTask` 时，gateway 端把 RPC `request_id` 当 `ActionId`，
  不影响 `source_task_id`（不同字段、不同语义）。
- 如未来加 RT emergency / pre-empt action，**仍**必须保 cmd_seq 单
  调；emergency body 的 source_task_id 必须从 `TickState.cmd_seq` 取
  （或扩 lib API 让 emergency 路径也能拿到 cmd_seq），不得新建私有
  counter。
