## 1. 范围 / 不在范围

- **5 个 task control plane RPC**（design §5.3 frozen schema 子集；A1
  ClearEStop 之外的 5 method 全做）：
  * `InvokeTask`（client → gateway → s1 RR `task_invoke` →

    起 events_subscribe thread 桥到 tonic streaming response）
  * `ClearError`（→ s1 RR `clear_error` → `Coordinator::clear_error`）

- **s1_daemon 加 4 RR server thread + events drain pubsub**：
  * `crates/robot-s1/src/rr_server/{mod,wire,handler,runtime}.rs` (~2000L

## 3. 关键契约审计（B4 引入 / 维护的硬约束）

### 3.1 source_task_id 单调（B3 §3.7 wire 契约保持）

B4 跨进程 wiring 期间**不**得在 gateway / s1 RR handler / events_drain
任一环节重写 `JointCommand.source_task_id`；wire 契约由 s1 coordinator
`TickState.cmd_seq` 单一 source 驱动（B3 已锁），B4 仅消费 `ActionEvent`
流（pubsub）+ s1 RPC handler 调 `Coordinator::{submit/cancel/status/
clear_error}` in-process API（不产 frame）。

**lib unit 锁测**：`crates/robot-rpc/tests/task_rpc_e2e.rs::wire_contract_source_task_id_monotonic`
跨进程订阅 `/<robot>/s1/<hw>/command` 验 ≥2 frames 严格单调（B4 (3/3)
AC-6）。

### 3.2 idempotency cache namespace（reviewer (2/3-b) 阻断锁定）

`IdempotencyCache::decide(method, key, fingerprint)` 内部用
`format!("{method}:{key})` 作 HashMap key；同 `idempotency_key` 在不
同 method 上调用 = 不同 cache 槽，**不**跨 method replay。

`CachedResponse` enum **不**强压 Invoke/Cancel 同 variant：
- `ClearEStop { cleared_at_ns, dry_run }` (A1 同款)
- `InvokeTask { action_id }` (TaskHandle response 字段)
- `CancelTask { cancel_at_ns, dry_run }` (fbs 字段名跟 ClearEStop
  cleared_at_ns 语义不同)
- `ClearError { cleared_at_ns, dry_run }` (独立 variant)

**lib unit 锁测**：`idempotency.rs::tests::method_namespace_isolates_same_idempotency_key`
+ 4 个 variant round-trip。

### 3.3 fingerprint 排除字段（A1 阻断 1 + B4 沿用）

跟 A1 同款约束：fingerprint **排除** `request_id` / `timeout_ms` /
`idempotency_key`，避免合法 retry（每次重试客户端生成新 v7
request_id + 可能调 timeout）误走 `Decision::Conflict`。

`task_handlers.rs::invoke_task_idempotency_fingerprint`：进 fingerprint
= source / audit_reason / dry_run / auth_token / kind / payload_schema_id
/ payload bytes；**不**进 = request_id / timeout_ms / idempotency_key
/ priority / deadline_ns。

**lib unit 锁测**：`task_handlers.rs::tests::invoke_task_fingerprint_excludes_request_id_and_timeout_ms`
+ AC-4 cross-process replay 测。

### 3.4 ActionRpcStatus → tonic::Code 显式 match + variant count lock

沿 A1 `rpc_status_to_tonic_code` 同款约束：禁止 `as i32` cast；必须
显式 `match` 全 variant。`ActionRpcStatus::ENUM_VALUES.len()` (=10)
跟 helper 显式映射数硬绑（lib unit
`action_rpc_status_variant_count_matches_explicit_mapping`）；新加
variant 让 length 对不上 → 测试失败强制更新 helper + 单测。

### 3.5 shutdown 顺序契约（reviewer round 5/6 阻断锁定）

`s1_daemon` shutdown **必须**按以下顺序，否则 RR thread stop-but-not-
join 期间 in-flight invoke 调 `register` 跟 `events_registry.stop_*`
撞 late register：

```text
1. coordinator.mark_shutting_down()        # 拒新 submit (→ Unavailable)
2. rr_handles.request_stop_all()           # 通知 RR thread 不接新 wire
3. rr_handles.join_all()                   # 等所有 in-flight handler 跑完
4. events_registry.stop_and_join_all()     # 等所有 drain thread 跑完
```

`EventsDrainRegistry::stop_and_join_all` 接 `&self`（reviewer round 6
阻断改造）—— 内部 `Mutex<Vec<Handle>>` `mem::take` 拿 owned `Vec` 后
锁外逐个 join；daemon 不依赖 `Arc::try_unwrap`（避免 ref-leak 编程
bug 时打破 join 确定性）。

**lib unit 锁测**：`rr_server/handler.rs::tests::shutdown_in_flight_invoke_rejected_no_register`
锁住 mark_shutting_down 后 invoke handler 必返 `Unavailable` 且
`registry.len() == 0`。

### 3.6 stream lifecycle / client disconnect 不通知 s1（outline §5.5 #3）

`StreamTaskEvents` 是 audit 通道，**不**是控制通道。client 主动 drop
response stream → gateway `EventsSubscribeStream::drop` set stop
signal → subscribe thread 1s 内退出 + iceoryx2 subscriber drop（**不**
给 s1 发 cancel signal）。客户端要主动停 task 必须调 `CancelTask`
RPC（明确意图）。

`EventsSubscribeStream` 用 detach + bounded self-exit 设计（drop 是
sync，join 阻塞 tokio worker 不可取）；`drop_stream_signals_stop_to_thread`
锁住 1s 内 stop_by_signal 被观察到。

### 3.7 pubsub keep-last 单 slot semantics（outline §5.5 #1）

iceoryx2 pubsub keep-last 单 slot；s1 publish 速率快 / gateway 端拉慢
会丢中间帧（最新 wins）。`adapter thread` `tokio::sync::mpsc::Sender::try_send`
满 → drop event + `tracing::warn!`，**不**阻塞（一致性 by 客户端自己
catch up `GetTaskStatus` 拿当前快照）。

**已知 wakeup race**：client 端 `events_subscribe_thread` 在
`invoke_task` RPC 返回**之后**才起，可能错过 s1 `events_drain` 在
invoke 返 Ok 之前 publish 的第一帧 `Started`（详 (3/3) AC-1 PASS
但断言改"events 非空 + 终态收到"）。outline §5.5 已 ack 此设计。

## 4. 跨进程 e2e harness 工程经验（B4 (3/3) 落地后回填）

cargo `tests/*.rs` 模式跑 6 子进程 spawn 整套，关键工程点（下次
v0.4+ 写跨进程 e2e 可直接参考 `crates/robot-rpc/tests/common/`）：

| 工程点 | 解决方案 |
|---|---|
| 6 个 `#[tokio::test]` 同进程并发 | `static GLOBAL_LOCK: tokio::sync::Mutex<()>` 强制串行；**禁止 std::sync::Mutex**（guard 跨 .await 是 anti-pattern）；同时推荐 `--test-threads=1` 双层防御 |
| `[[test]] required-features` | gRPC client stub feature gate（A1 拍板 production 不带 client）；让 `cargo test --workspace --all-targets` 默认跳过；CI 显式 `cargo test --features client --test task_rpc_e2e` 才跑 |
| 子进程清理 | `tokio::process::Command::kill_on_drop(true)` + `Drop for CaseCtx` SIGTERM 3s grace → SIGKILL fallback；test panic 路径靠 RAII 兜底 |
| iceoryx2 service 名隔离 | `CASE_SEQ + std::process::id()` 派生唯一 robot_id；同 PID 重跑靠 seq 自增 |
| s1_daemon anchor 通过 | 测试侧扮演 s0 角色：起 `FakeStatePublisher` 50Hz publish JointState 给 `/<robot>/s0/<hw>/state`；**不**起真 s0_daemon。**关键**：用 `robot_core::time::SystemClock::now()` 拿 monotonic ns 填 stamp_ns，跟 s1 `read_anchor_from_s0_state` 同 clock domain（max_stale_ms=200ms 才能通过） |
| 三段式 ready | (1) wait s1 marker `"rr_server_threads ready"` (5s) → (2) wait gateway marker `"rr_io_threads started"` (5s) → (3) TCP probe listen_addr (500ms / 50ms retry) → (4) RPC probe `GetTaskStatus { unknown_id }` 期 NotFound (5s / 100ms retry)。各段失败 fingerprint 各异；总 wall ≤ 11s/test |
| forensic | `Stdio::piped()` + 2 个 tokio task drain stdout/stderr → `Arc<Mutex<Vec<String>>>` + `eprintln!("[{label}/{stream}] {line}")` 转发；失败时 `Drop` 输出 robot_id / listen_addr / daemon_pid / gateway_pid / action_ids；可选 `dump_captured_to /tmp/b4_e2e/<robot_id>/{daemon,gateway}.stderr` |
| 测试 toml | **不**写 `[s1]` / `[s1.profile]` 段（`S1Section` `deny_unknown_fields` 跟 `[s1.profile]` 冲突）；仅写 `[[hardware]]` 让 `ProfileSection::default_b2()` 跑 `mock_dwell + joint_position`，跟测试路径完全等价 |
| Wire 契约验证 | 测试侧 `iceoryx2 sub` 直接订阅 `/<robot>/s1/<hw>/command`（S0Command max_sub=1，测试是唯一 sub；s0_daemon 不在拓扑里所以不冲突）；从 fbs `JointCommand.source_task_id()` 验严格单调 |
