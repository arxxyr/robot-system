## 3. 关键契约审计（候选 2 round 1 引入 / 维护的硬约束）

### 3.1 trait dyn-safe + 编译期 monomorphize 锁（reviewer 审查重点 #1）

`ArmIkSolver: Send + Sync` 严格 dyn-safe（Q6 ACK）：方法签名不含
generic param（除 `Self: Sized` bound）/ 不返 `Self`；可作
`Box<dyn ArmIkSolver>` 存于 S1 coordinator（round 2 wiring）。

锁测两层：
- **lib.rs trait doc § dyn-safety**（`crates/robot-kinematics/src/
  lib.rs:117-122`）—— 显式声明 dyn-safety 契约；如未来扩 trait 引
  入 `Self` 返 / generic method，doc 段必须同步改 / 锁测必须同步 fail
- **`assert_dyn_safe::<dyn ArmIkSolver>()` 编译期 monomorphize**
  （`crates/robot-kinematics/src/lib.rs:270-278`）—— `fn
  assert_dyn_safe<T: ?Sized + ArmIkSolver>() {}` + `#[test] fn
  arm_ik_solver_is_dyn_safe()` 内调用 `assert_dyn_safe::<dyn
  ArmIkSolver>()` 强制单态化 `dyn ArmIkSolver` —— 若 trait 非
  dyn-safe，`dyn ArmIkSolver` 类型本身无法构造 → 本行编译 fail
  → CI / 本地 `cargo test` 立刻爆

**为什么不是 `assert_obj_safe!` macro**：Plan round 1 拍板 #4 (a)
选 `assert_dyn_safe` 单测（沿候选 1 monomorphize 锁测同款模式）；
`assert_obj_safe!`（`static_assertions` crate）= 新 dev-dep，违反
Q3(i) 零依赖原则。

**为什么命名不带 `_` 前缀**：workspace 启用 `clippy::used_underscore_
items` lint —— underscore 前缀的 item 被使用就报错；故命名
`assert_dyn_safe` 而非 `_assert_dyn_safe`（详 §7 diff #4）。

### 3.2 `IkError` 5 variant exhaustive match 锁（reviewer 审查重点 + AC-4）

`IkError` 5 variant（Q2(α + `InvalidInput`) ACK）+ `thiserror::Error`
derive，**严禁** `Box<dyn Error>` 字段（候选 β 反例已拒）。

exhaustive match 锁测（沿候选 1 `action_kind_three_v04_variants`
同款模式）：

```rust
fn variant_name(e: &IkError) -> &'static str {
    match e {
        IkError::InvalidInput { .. } => "InvalidInput",
        IkError::NoSolution => "NoSolution",
        IkError::OutOfReach { .. } => "OutOfReach",
        IkError::SingularityTooClose { .. } => "SingularityTooClose",
        IkError::DeadlineExceeded => "DeadlineExceeded",

}
```

`#[test] fn ik_error_variant_exhaustive()` 5 variant 全构造 +
`assert_eq!` 字符串映射。若未来扩 variant（例如 round 2 `IkBackend`
发现需要 `ConfigError { path }` 第 6 variant）漏处理本 `match`，编
译期 fail —— **不**留 `_ =>` 兜底（保 exhaustive 锁）。

### 3.3 trait 层不预钉 `XLeRobot` clamp 行为（reviewer 审查重点 #3 + AC-6）

trait 层**不**强制 solver 报告 clamp 行为。`IkSolution` **最小**字

`residual_error` 等 metadata） + `IkError::OutOfReach` 在 trait 层
**可选**返回：

- solver 实现**可以**返 `Ok(IkSolution { joints_rad: clamped_to_
  workspace })` + 配套外部 informational metric（如 `tracing::warn!`）
- solver 实现**也可以**返 `Err(IkError::OutOfReach { distance_m })`
- trait crate **不强制**语义

**XLeRobot impl（round 2）按 dimos `arm_ik.py` 现有 fail-safe clamp
行为**或**重新拍板**；本 round 1 trait 层**不**预钉。

四处双写防漂移（高于 Plan 倾向的"三处双写"，因 README 拍板 (b) 不落

### 3.4 `deadline_ns: Option<u64>` 仓库统一时间模型对齐

trait `solve` 签名 `deadline_ns: Option<u64>`（**不**用 `Option<i64>`
/ `Option<u128>`）—— 跟 `robot-core::time::MonoRawNs(u64)` +
`Deadline(MonoRawNs)` + `crates/robot-s1/src/action.rs::ActionRequest.
deadline_ns: u64` 仓库统一时间模型对齐。

**trait crate 不 dep robot-core**：仅**值语义对齐**避免 signed
conversion 损失精度 + 跨 crate 转换无意义 cast；保持 trait crate 顶
层零内部 dep（§4.1 + §4.2 设计原则）。

语义：
- `None` = 无 deadline（无限等待）
- `Some(ns)` = 绝对超时 ns from `CLOCK_MONOTONIC_RAW`；solver 内部自
  查 + 返 `IkError::DeadlineExceeded`

**round 2 接入预期**：S1 coordinator 把 `ActionRequest.deadline_ns:
u64`（既有字段）作为 `Some(deadline)` 透传给 `solver.solve(...,
Some(deadline_ns))`；无 signed conversion / 无 cast 必要。
