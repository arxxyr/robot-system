### 3.1 Step 9: EStop latch crash/restart 测试套（commit `01f7809` + `2a1640e` + `df6e207`）

**目标**：锁定 `docs/00_design.md` §6.7 不变量 #3 (EStop 不可清为失忆态)
+ #4 (S0 重启不失忆) 在 SIGKILL 路径下成立。

**实现**：`crates/robot-tests/src/bin/crash_restart_smoke.rs` —— 一个
binary，可重复跑场景 `kill_after_estop_fsync_window`：

1. spawn s0_daemon + mock_s1 (`--amplitude 0.0 --frozen-joints 6,7,8`)
2. settle 3s 让 state=Enabled.Active
3. robotctl estop 触发
4. sleep 500ms (fsync grace > 实测 188-255ms 窗口)
5. **SIGKILL daemon**（`libc::kill(pid, SIGKILL)`，**不**给 graceful
   shutdown 机会）
6. 读 latch primary + bak，断言**都 = "1"**
7. 重启 daemon 短跑，捕 stdout+stderr，按结构化字段（`initial estop_latched`
   message + `latched=true` 或 `"latched":true`）断言

**reviewer 阻断 + 修复历史**：
- reviewer round 2: 发现 commit `8e5a238` task #16 把 daemon
  "initial estop_latched = ..." eprintln 迁到 tracing，旧 grep 字串失
  效。修：commit `2a1640e` 加 `log_contains_initial_latched_true` +
  7 条 unit test（含**回归锁** 钉死旧字串）。
- reviewer round 3: 真机 5/5 还是 FAIL —— tracing 默认输出 stdout 不
  是 stderr + ANSI 转义码。修：commit `df6e207` 抓 stdout + env 注入
  `ROBOT_LOG_FORMAT=json + NO_COLOR=1`。

**真机验证（Orin，最终）**：5/5 PASS。

```

  ✓ restart daemon: initial estop_latched (latched=true)
```

### 3.2 systemd Type=notify 双 bus 集成（commit `4eeb584` + `df9c361` + `2a1640e` + `f88e2ab` + `e2e7e30`）

**目标**：`docs/00_design.md` §6.7 不变量 #2 "systemd 是最外层看门狗" 落地。

**实现**：

- 新模块 `crates/robot-s0/src/systemd_notify.rs`（~150 行，**无新 dep**）：
  * `notify(READY=1 / WATCHDOG=1 / STOPPING=1 / STATUS=<text>)` 协议
    最小实现，UNIX `SOCK_DGRAM`
  * `NOTIFY_SOCKET` 未设置时 silent no-op（dev / runbook / crash_restart_smoke
    场景零差异）
  * `spawn_watchdog_thread` 读 `WATCHDOG_USEC` env，按 `usec/2` 周期 ping
- s0_daemon main 集成（§8c）：
  * 所有 4 线程 spawn 后调 `systemd_notify::ready()`
  * `spawn_watchdog_thread` 起独立 watchdog ping 线程
  * Graceful shutdown 顺序：`stopping()` → 停 ping 线程 → `graceful_stop`
    （注释明确顺序原因 = 防 systemd 在 graceful 期间 watchdog 误杀）
- `scripts/systemd/xlerobot-s0-bus2.service`（9-motor 右臂+底盘）：
  * `Type=notify` + `WatchdogSec=2s` + `Restart=on-failure`
  * `Conflicts=xlerobot-coordinator/web`（dimos 互斥）
  * `Requires=dev-ttyACM1.device`（USB 枚举完才启动）
  * `User=loosqk` + `SupplementaryGroups=dialout`（user 模式串口访问）
- `scripts/systemd/xlerobot-s0-bus1.service`（8-motor 左臂+头部）：同模板
- `configs/xlerobot_bus1_full.toml`：bus1 = ttyACM0，joints = left_arm 6 +
  head 2 (head_motor_1 = pan, head_motor_2 = tilt)

**reviewer 阻断 + 修复历史**：
- reviewer round 2 阻断 1（高）：`PrivateTmp=yes` 隔离 `/tmp/iceoryx2`，
  daemon 在私有 /tmp 创建 service，宿主 mock_s1 / robotctl 看不到 →
  通信完全断。修：commit `2a1640e` 删 `PrivateTmp=yes`。
- reviewer round 3：删 PrivateTmp 后 daemon 仍在 systemd 下 panic
  `iceoryx2 NodeBuilder::create::<IxService>` InternalError。Bisect 找
  到 `ProtectSystem=strict` 让 iceoryx2 写 /var 失败（即使 ReadWritePaths
  显式列了）。修：commit `f88e2ab` 降到 `ProtectSystem=full`（/var 可
  写，/usr /boot /efi /etc 仍只读）。
- reviewer round 3 阻断附加：unit 注释里残留 "sleep 5 等 Enabled.Active"
  不严谨。修：commit `e2e7e30` 注释跟 README 同步成 "sleep 3 等
  Ready"，加注意段说明 unit 只启 S0 不进 Active。

**真机验证（Orin，最终）**：

```bash
# systemd 启 bus2 daemon
$ sudo systemctl start xlerobot-s0-bus2
$ systemctl is-active xlerobot-s0-bus2  # active

# 阻断 1 真机：宿主 mock_s1 + 2 watch + robotctl estop 跨进程
$ target/release/mock_s1 ... --joints 9 --amplitude 0.0 --frozen-joints 6,7,8 ...
$ target/release/robotctl watch ...  # A: 20 sample
$ target/release/robotctl watch ...  # B: 20 sample（双 watch 同时通）
$ target/release/robotctl estop --reason "blocker-1-final"
  # → daemon journal: "state":"Safe","guards.estop":true (~200ms 内)
  # → latch primary+bak: 1 / 1（fsync 落盘）

# Watchdog 真重启路径
$ sudo kill -9 $(systemctl show -p MainPID --value xlerobot-s0-bus2)
$ sleep 4
$ systemctl is-active xlerobot-s0-bus2  # active（新 PID）
  # journal 看到第二次 "s0_daemon starting" + 第二次 state=Ready
```

✅ §6.7 不变量 #2 真机锁住。

- `crates/robot-s0/src/rt_thread.rs`：3→0（**RT 边界说明**：3 个 apply_*
  helper 在 spawn 后、tick loop 之前的 startup setup 阶段执行，非 hot
  path；tick loop 内仍**严禁** `tracing::*!`，已加块注释明确边界）

`guards.estop` / `latched` 全部可索引）。
