### 3.1 `source_task_id == ctx.command_seq` 跨 segment 严格单调（B3 §3.7 延续）

### 3.2 phase 状态机大步推 clock 收敛（Dwell `start_ns` 锚定 Interp 自然完成时刻）

`ScriptedInstance::tick()` Interp 完成 → 切 Dwell 关键设计：

```rust
let dwell_anchor = start_ns.saturating_add(segment_duration_ns);
if now_ns.saturating_sub(dwell_anchor) >= dwell_ns {
    return Ok(self.advance_waypoint_and_emit(ctx, now_ns));
}
self.phase = Phase::Dwell { start_ns: dwell_anchor };
```

**Why**：`Dwell.start_ns` 用 Interp 自然完成时刻（`original_interp_
start + segment_duration_ns`），**不**用 `now_ns`。当 tick 间隔大步
推（如 `tick_completed_after_last_dwell` 单步推 1s 跨整段）时：

- 若用 `now_ns`：Dwell 期 elapsed = 0 → 永远不退出 Dwell；多段长
  duration script 单 tick 无法收敛
- 用 Interp 自然完成时刻：Dwell elapsed = `now_ns - dwell_anchor`
  自然累计；下一 tick 立即看到 Dwell 超时就 advance；末段直接返
  `Completed(Success)`

lib unit `tick_completed_after_last_dwell` 覆盖大步推过总时长场景。

### 3.3 cancel 语义两层分离（backend lib `PartialSuccess` ↔ coordinator `ActionEvent::Cancelled`）

Q4(a) reviewer round 1 拍板 + Plan round 2 阻断 2 复核：

### 3.4 两道 byte gate `CONTROL_TIER_MAX_BYTES` 单源绑定

`crates/robot-rpc/src/task_handlers.rs`：

```rust
pub(crate) const MAX_SCRIPTED_PAYLOAD_BYTES: usize = 4 * 1024;
pub(crate) const CONTROL_TIER_MAX_BYTES: usize =
    robot_msg::size_tier::SizeTier::Control.max_bytes();

    assert!(MAX_SCRIPTED_PAYLOAD_BYTES < CONTROL_TIER_MAX_BYTES);
```

`SizeTier::Control.max_bytes()` 必须自动联动 Gate 2，避免 schema 端
改 tier 而 gateway gate 漏改。`_GATE_BOUNDARY_CONST` 编译期断言两道
gate 互不矛盾（Gate 1 ≤ Gate 2 严格保留逐层 deepening）。

候选 1 验证：

### 3.5 `ActionRpcStatus` 错误码映射（Q9 拍板 + AC-7 三层穷举）

| backend / dispatch error | wire `ActionRpcStatus` | tonic `Code` |

- 7a empty waypoints → `FailedPrecondition` ✓

- 7c-i 4 KiB + 1 payload → Gate 1 `InvalidArgument` ✓
- 7c-iii 1 KiB 0xFF garbage payload → backend `PayloadDecode` →
