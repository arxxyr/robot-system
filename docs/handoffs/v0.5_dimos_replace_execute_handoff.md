## 3. 与 reviewer 协作的工作方式（跨候选沉淀，只在对话里）

1. **节奏三态**："不 ACK，先别 push" / "条件 ACK：补 §P.4 登记后可 push" / "代码层 ACK"。
   每段 = feat 本地 commit → 完成报告（`git log --oneline -4` + `git status --short` + gate
   数字 + 可复核 file:line）→ ACK 才 push → 登记 docs → 下一段；助手以"要现在开吗？"收尾，
   **不自行开下一段**。reviewer 核 `master ahead origin/master N` 顺序。预授权形态存在
   （"修完即 push，不用重发报告"），仅限 push 前小 amend。
2. **打回处理**：未 push → **amend 原 commit** 报新 hash；已 push → 独立 fix commit；折叠重提
   （`git reset --soft`）后**全仓 grep 旧 hash**（候选 A (5/5) 4 文件 5 处、候选 B 4 锚点
   都因此再挨一轮）。
3. **拆分**：feat/build 与 docs 分开；summary 不与实施混（两次强调）；`Cargo.lock` 随 feat
   （段(2)/(4) 两次漏在 feat 外）；行为 vs 字面同步混提须 body 明文标注（memory
   `feedback_commit_split_behavior_vs_literal`）；计划外 docs commit 也进 chain，"避免最终
   '5 commit + summary'计数不准"。
4. **RIPER 顺序硬性**：CodeMap → Spec → Plan → Execute；"CodeMap 后再开 Spec，不要边摸边
   写代码"；Spec 阻断未清零"不批准直接进 Plan"；Plan Approved 前"必须到文件/函数/测试名级"
   且不实施；Plan 写在 Spec 同文件 `## Plan` §P.0-P.4；"进入 Execute 前把基线同步到当前
   Plan commit"。偏离："任何 Plan 偏离先登记 §P.4，再继续"；**Reverse Sync = 先修 Spec 再
   改代码**（"这不是改需求，是代码回到已拍 Spec"）。P.4 只登 Plan-Execute diff（注释精确化、
   测试可执行化不登；**故意改资源生命周期**——如 mem::forget——必登，哪怕设计可接受；宁可
   多标让 reviewer 裁）。reviewer 指定 PX 编号。
5. **reviewer 从不跑全量 gate**（每轮自述"本轮是 diff/code review"），**报告数字是唯一证据**
   → 假性宣称只能自己抓（候选 C (4/5) 曾 push 假性"0 退化"，e2e 跑的是旧 release gateway，
   RS2 由此而来；段(2) 同根因再被判"证据无效"）。reviewer 会本地复跑轻量命令（`cargo test
   -p <crate>`、`--no-run`、`cargo tree --help`、`git status`）、grep 精确短语/旧 hash/import
   边界、对账行数与 PASS 数、必要时自己做最小复现。
6. **文档事实纪律**：commit 链完整且计数一致；不写硬行数；文档日期 = commit 日期；不留
   `](https://)` 占位；不预决（禁"已锁""必落"，写"倾向 X，Spec/Plan 拍板"）；AC 口径 = 实际
   断言，AC 必须可验证；cargo deny 只写"未新增 violation；overall FAILED 为既有 baseline"，
   **禁"通过"**（三次重申）；非安全保证显式标注（"不能把 read_state cap 写成已实现安全
   属性"）；不过度宣称（"不要在 summary 里写'panic 路径也规避'"；AC-4 "Progress 序列单调"
   被降为实锁项）；summary 表逐 hash 一行，禁"本段"折叠；summary 自身写"本 docs commit"
   不自引用 hash；Q/PX 编号跨文档稳定、新增顺延；引用归属分清。
7. **并发注释写真实机制**（Mutex / join），不写 cadence（候选 3 (ii) 三处语义注释）。
8. **半成品不落 master**：可达的 `unimplemented!()` 不可留（parser variant 随对应实现
   commit 落地）；悬空 `[[bin]]` 不留；宁可干净 checkpoint + entry handoff（候选 A (5/5)
   reviewer 原话："最大风险不是慢，而是产出一个'看起来有 harness、实际跑不稳'的半成品"）。
9. **同款洞一起收口"不是过度修复"**（候选 A D6 六子命令全拒）；"flag 在哪段暴露，语义就
   在哪段锁"（timeout→exit 6 不推后）。
10. **场外一句提问 = 触发盘点**（"全部的 gateway 都验证了吗" → PE3；"是否还需要看门狗" →
    SAFE-B1..B4）；reviewer 期待主动盘点验证面，回答架构级"缺不缺"时不要下"已齐"结论。
11. **上下文压缩后回放的旧 ACK（caveat 包裹）≠ 新 ACK**，不得据此开下一段（05-26 先例）；
    reviewer 重复消息 = 重发不是新 round（05-13 rate-limit 先例）；reviewer 可能基于旧快照
    复核（§2.2 23:31 先例）。
12. **用户的"我push了"视同 ACK**；docs-only 轮"纯 CodeMap 文档，我不要求跑 Rust 质量门"，
    但零代码时仍跑 fmt/clippy 并在报告里说明未跑 test 的理由；无 manifest/lock 变更 deny
    可不重跑。全程中文，emoji + type 无 scope，不加 Co-Authored-By。
