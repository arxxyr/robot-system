## 3. 关键契约审计（候选 3 引入 / 维护的硬约束）

### 3.1 `EventsDrainRegistry::reap_finished(&self) -> usize`

`reap_finished` 接 `&self`（沿 `register` / `request_stop_all` /
`join_all` / `stop_and_join_all` 同款 by-ref 约定；B4 reviewer round 6
阻断契约延续）；返"本次从 registry 移除并 join 尝试的 handle 数"——
**含 drain thread panic 路径**（panic 也 counted as reaped；不区分 join
Ok / Err）。

**并发互斥本质** = registry 内部同一把 `Mutex`：
- 锁内 `JoinHandle::is_finished()` + `swap_remove` 已退出 thread 的
  handle 进 owned `Vec`
- 锁外逐个 join + `tracing::warn!` 记录 panic（不传播）

跟 `stop_and_join_all` 协作：reap 后 inner Vec 仅含活 handle，
`stop_and_join_all` (`mem::take` 整 Vec → 锁外逐个 stop+join) 行为跟
reap 前后完全等价；重复调任意组合 = no-op。

**4 lib unit 全 PASS**（详 §1.1）。

### 3.2 shutdown 顺序契约（reviewer round 6 + AC-C1 outline §4 拍板）

```
1. coordinator.mark_shutting_down       ← 拒新 submit
2. rr.request_stop_all                  ← 通知 RR thread 不接新 wire
3. rr.join_all                          ← 等所有 in-flight handler 跑完
4. (v0.4 候选 3 AC-C1) reaper.stop + join  ← 停 reaper thread
5. events_registry.stop_and_join_all    ← 等剩余 drain thread 跑完
```

**关键 invariant**：step 4 在 step 5 之前彻底 join reaper，让 step 5
看到稳定 inner Vec；reaper 跟 stop_and_join_all 的**并发互斥本质**
是 registry 内部 `Mutex`，**不**是 reaper cadence（1s sleep 仅影响
shutdown 最坏等待时间 ≤ 1s，**不**是互斥保证）。

shutdown 顺序 lib unit 保不变（B4 / v0.4 全保）：
- `shutdown_in_flight_invoke_rejected_no_register`
- `registry_stop_and_join_all_handles_empty`
- `registry_stop_and_join_all_one_thread`

### 3.3 reaper log cadence + smoke 端 scrape 强耦合

reaper thread `reaped > 0` 时 `tracing::info!` 显式打
`events_registry_len`（AC-C1 outline §3 reviewer round 1 阻断 2 拍板：
没这行 scrape 永远读到最后一次 register 累计值，误判 C1 未收敛）。

smoke binary `scrape_events_registry_len` 倒序扫 captured 取最近值，
覆盖 4 类打点：
- `handle_invoke` 成功 register 后即时
- s1_daemon `shutdown_pre` / `shutdown_post`
- AC-C1 reaper `op="reap"` (每次 `reaped > 0`)
- AC-C1 reaper `op="reaper_stopped"` (shutdown step 4 完成)

**强耦合约束**（Plan-Execute diff #3 登记）：smoke `run_phase_a1` final
sample 前 sleep **2000ms** (= 2× reaper cycle + terminal_grace + margin)
跟 reaper cadence 强耦合；改 reaper period 必须同步改 grace（或反之）。

### 3.4 AC-A2 时钟域硬约束（Plan v3 §P.2.2.b）

`latency_ns = client_receive_ns - event.at_ns`：

- `client_receive_ns` **必须**用 `robot_core::time::SystemClock::new().now().0`
  （CLOCK_MONOTONIC_RAW，跟 s1 端 `event.at_ns` 同 clock domain）
- 反向 (`client_receive_ns < event_at_ns`) → forensic dump + smoke
  fail (`clock_domain_violation`)；**不**用 `saturating_sub` 掩盖
- smoke binary 跟 s1_daemon / gateway **必须同机器**跑
