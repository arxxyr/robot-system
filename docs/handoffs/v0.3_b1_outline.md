## 2. coordinator 线程 / 任务模型

设计文档 §6 列了 `coordinator.rs` 主循环 `READ → COMPUTE → ARBITRATE
→ ROUTE → WRITE`。B1 简化到 `READ_STATE_ONCE → TICK_LOOP {
build_hold_cmd → publish_command + heartbeat }`。

### 2.1 主线程模型

```text
main()
  ├─ install_signal_handlers (SIGINT / SIGTERM → AtomicBool)
  ├─ cli::Args::parse
  ├─ load_robot_config（robot-s1 内 self-deserialize 同款 TOML：
  │   读 [robot] + [[hardware]] + 可选 [s1] section；不 link
  │   robot-s0::config_loader，避免 s1→s0 倒挂）
  ├─ open iceoryx2 publishers (s1/<hw>/command, s1/heartbeat)
  ├─ open iceoryx2 subscriber (s0/<hw>/state) ── 仅启动期 + idle 阶段
  │   轻量 poll
  ├─ anchor: read_anchor_from_s0_state(timeout) → bias[0..joints]
  ├─ tick_loop {
  │     while !SHUTDOWN.load() && !duration_elapsed() {
  │         now = clock.now()
  │         if now - last_cmd_ns >= cmd_period_ns {
  │             body = build_hold_command(bias, deadline=now+500ms,
  │                                       on_timeout=Hold, stale_action=Hold,
  │                                       seq)
  │             publish(body)
  │         }
  │         if now - last_hb_ns >= hb_period_ns {
  │             body = build_heartbeat(source_id=2, seq, hb_hz, now)
  │             publish(body)
  │         }
  │         sleep(1ms poll)
  │     }
  │ }
  └─ graceful: drop publishers (B2 起接 sd_notify STOPPING=1)
```

**单线程**够用（B1 无 RT 路径，发布频率 50 Hz，sleep 1ms poll）。S1 真出
现 jitter 影响时再考虑把 publish loop 拆 dedicated thread + 单独
signal thread。

### 2.2 何时**不**发命令？

设计文档 §1.6 "S1 coordinator/arbiter 允许 publish `/s0/<hw>/command`"
是无条件的。B1 默认**永远**发（即便 S0 在 `Safe` / `Fault`），因为：

- 让 S1 看 S0 state 来决定是否 publish 是 §6.3 反向耦合；S0 自己有
  EStop latch + state machine guard 拦掉不该执行的 command。
- B1 简单语义：S1 是"持续报心跳 + 持续报 idle hold target 的进程"；S0
  是真权威，按自己 state machine 决定是否执行 command。

留一个**可选 graceful guard**（B2 决策）：S1 看到 S0 state == `Fault`
时 backoff 发布频率到 1 Hz（避免淹没 S0 IPC channel）。B1 不做。

## 4. 发 heartbeat / command 的时序

### 4.1 频率

- `Heartbeat`: 50 Hz（design §3.5 + §6.2 "S1 → S0 50 Hz"）。
- `JointCommand`: 50 Hz（跟 `mock_s1` 默认对齐；S0 watchdog 200 ms 超
  时，单 50 Hz 心跳 + 命令的 cushion 是 10 个 cycle）。
- 两个独立计时器，各自累加 seq；时间基准 `SystemClock`
  (`CLOCK_MONOTONIC_RAW`)。

### 4.2 启动期顺序

```text
1. open publishers (cmd + heartbeat)        ── 失败立即 exit 1
2. open subscriber (s0 state)
3. wait_for_first_state(anchor_timeout_ms)  ── 锚定 bias
                                             读不到（daemon 还没起 /
                                             state topic 没流量）→
                                             **fail-fast** 退出非 0
                                             （reviewer 拍板：B1 是生产
                                             S1，生命周期上 s0 必须先
                                             ready；deploy 流程 systemd
                                             `After=s0_daemon.service`
                                             锁定，留 v0.4+ 真部署补）
4. close subscriber                          ── 锚定后不需要继续 poll
                                             （B2 加 DEGRADED 监听后再开）
5. enter tick_loop (publish heartbeat + hold command)
```

### 4.3 关停序

```text
1. SIGINT/SIGTERM → SHUTDOWN.store(true)
2. tick_loop break，return (drop publishers 关 iceoryx2 ports)
3. 不写 latch / 不调 ClearEStop / 不发 EStop
   ── S1 只是 coordinator，不参与 safety latch
```

## 5. 如何保持安全默认

### 5.1 hold / idle 真路径

- `JointCommand.target` = `bias`（启动期锚定的当前位置）。
- `JointCommand.control_mode` = `Position`。
- `JointCommand.deadline_ns` = `now + 500 ms`（每帧重新计算）。
- `JointCommand.on_timeout` = `Hold`（让 S0 看到 cmd 过期时
  `ENABLED.CONTROL_LOST_HOLD`，保持最后一次位置）。
- `JointCommand.stale_action` = `Hold`（即便 cmd 来了但 S0 内部判断
  stale，也 Hold）。

### 5.2 deadline 计算

deadline 必须是 monotonic absolute 时刻（design §6.6）。S1 跟 S0 共享
`CLOCK_MONOTONIC_RAW`，B1 用 `clock.now().0 + 500_000_000`。

### 5.3 EStop / latch 交互

S1 **不**参与 EStop / ClearEStop：

- EStop 触发链路：外部（GPIO 按钮 / RPC `EStop` action）→ 直接落到
  S0；S1 不接 estop 事件 topic（design §1.6 "S1 不发 events/estop"）。
- ClearEStop：走 RPC gateway → S0 ipc_thread RR drain → action layer。
  S1 不参与（reviewer A1-1 拍板）。
- B1 即便看到 S0 state 是 `Safe`（EStop latched），仍按 50 Hz 发 hold
  command + heartbeat。S0 自己拦截 command 不真执行 motion；heartbeat
  让 S0 知道 S1 还活着。

**安全论证**：B1 永远发 hold target = anchor 位置（启动期 read 一次后
不变）。最坏情况 S0 状态机 bug 让 command 真到 hardware → motor 收到
的是当前位置（差值 0）→ 物理上不动。

## 6. mock_s1 哪些迁移、哪些保留

### 6.1 迁移到 s1_daemon（lib 纯函数）

- `read_anchor_bias`：启动期读 S0 state subscriber 一次拿当前位置 →
  `Vec<f64>`。提到 `crates/robot-s1/src/lib.rs` 作 `pub fn
  read_anchor_from_s0_state(...)`，单测覆盖（mock subscriber）。
- `build_hold_command`：构造 hold `JointCommand`（target = bias，模式
  Position，超时配置）。lib 纯函数，单测覆盖。
- `parse_duration` / 信号处理 / iceoryx2 publisher 构造模板：直接复用
  模式（不需要严格代码共享）。

### 6.2 保留 mock_s1（不删）

- 保留 `mock_s1` binary：sine ballet + amplitude / frequency /
  frozen_joints CLI 仍是真机 ballet 验证（task #15 Stage 1 / 2 在 Orin
  上跑 6-motor 摆动，`s1_daemon` 的 hold 用例完全不能替代）。
- 在 `mock_s1` 顶部 doc 说明 **mock_s1 = bench / ballet 工具**，不是
  production S1；production 走 `s1_daemon`。

### 6.3 不迁移

- `mock_s1` 的 sine 公式 + 多 joint 相位偏移：是 ballet 测试逻辑，不是
  production 行为。
- `--frozen-joints` mask：ballet 专属（frozen 是为了让某些 joint 在摆
  动测试时不动）。`s1_daemon` 全部 hold，无概念。
- amplitude / frequency CLI：同上。

- `read_anchor_from_s0_state` 各路径：拿到 state 内 N joints / state

- coordinator 配置加载：缺失 `[s1]` section → 走默认；显式覆盖 → 覆盖
  生效；非法值（`heartbeat_hz <= 0` / `deadline_ms == 0`）→ 报错。

iceoryx2）。

  → 断言 frequency ~= 50 Hz、target == bias、deadline 单调。
- mock S0 publisher 推一帧 state（`positions = [1.0, 2.0]`）→ 单 tick
  后 coordinator 读到 → bias = `[1.0, 2.0]` → hold command target ==
  bias 不变。

### 7.3 smoke / e2e 切到 real s1

  gate）；不动。
- **`freeze_systemd_smoke`**：A2 freeze hook 测试，不依赖 S1；不动。

### 7.4 真机回归（B1 不要求）

Orin / 真硬件回归留 B2 / 真机 ballet 阶段；B1 在 dev box `mock_hard_rt`
