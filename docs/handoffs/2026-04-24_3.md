## 3. 关键技术决策（对照 plan 的 architecture decisions）

### 3.1 修正：`ManipulatorAdapter` 签名是 9 方法

plan 初稿只列了 5 个（`info / read_state / write_command / set_mode / limits`）。**实际 `docs/00_design.md` §4.4 有 9 个**（多了 `connect` / `disconnect` / `enable(bool)` / `safety_stop`），Explore agent B 原先是对的。Part 1 已按 9 方法版本落地，`MockHardRTAdapter` 全部实现 + 测试覆盖 `safety_stop` 的 latch 语义。

### 3.2 同步原语方向性落地（plan 的核心决策，用户在 AskUserQuestion 确认后再修 plan）

| 方向 | 原语 | crate/file | RT 侧成本（测试验证） |
|---|---|---|---|
| `ipc_thread` 写 → `rt_thread` 读 | arc-swap（hazard pointer Guard，不 bump refcount） | `robot-transport/src/command_slot.rs` | `load()` Guard 不改 `Arc::strong_count`（`load_guard_does_not_bump_strong_count` regression 守卫） |
| `rt_thread` 写 → `pub_thread` 读 | 手写 seqlock（2×u64 version + `UnsafeCell<T>` + memcpy） | `robot-transport/src/snapshot.rs` | 3×reader + 1×writer 压测 100k 样本 0 撕裂（`stress_concurrent_readers_see_consistent_values`） |

POD 强制（`T: Copy` + `#[derive(Copy)]`）编译期阻止 `Vec` / `String` 字段进入 snapshot 载荷，这是 seqlock 的 type-level 前置条件。

### 3.3 RT guard 双层守卫

- **`RtArc<T>` + `RtArcGuard`**（无 feature gate）：始终活跃。thread-local `RT_IN_SCOPE` flag；`RtArc::clone` / `Arc::drop` 在 scope 内 panic。测试 5 条（enter/drop、禁嵌套、deref OK、clone panic、drop panic）。
- **`assert_no_alloc` bridge**（feature gate `rt_guard`，默认 off）：`assert_alloc_scope(|| ...)` 在 feature on 时调 `assert_no_alloc::assert_no_alloc(f)`，off 时等价 `f()`。`rt_entry!` 宏把两者打包。

Part 1 的 `s0_daemon` 默认不开 `rt_guard`（binary 侧要设 `#[global_allocator] static _: AllocDisabler = ...` 才生效）。Part 2 baseline 跑之前开 `rt_guard` + 补 binary 端 allocator 声明。

### 3.4 State machine shape 冻结 5 主态（用户本 session 修正）

Plan 初稿只写 SAFE/READY/ENABLED.ACTIVE 三态"真运行"；用户指出 5 主态 enum shape 落盘几乎零成本，避免 Part 2 回来改结构 + 重跑单测。**落地**：`enum S0State`（Safe/Ready/Enabled{sub,control_link,output_mode}/Fault(FaultCode)/Stopping）+ `enum EnabledSub` 4 子态 + `enum Event` 12 事件 + `try_transition` 覆盖完整表。**触发源区分**（见 `state_machine.rs` 模块 doc 表格）：

| 事件 | 触发源 | Part 1 可用 |
|---|---|---|
| `Enable` / `Heartbeat` / `EStop` | 测试或 RPC 注入 | ✅ |
| 其他 9 个事件 | watchdog / rt_thread 检测 / RPC / systemd（Part 2） | 仅单测注入 |

25 个单测**覆盖完整转换表**，包括 FAULT / STOPPING / CONTROL_LOST_* 的"变体存在"测试。

### 3.5 `panic = "abort"` 落到 workspace 级别

Plan 初稿写 `[profile.release.package.robot-s0] panic = "abort"`——**Cargo 不允许 per-package panic override**（报 `panic may not be specified in a package profile`）。改成 workspace 级 `[profile.release] panic = "abort"`。当前 workspace 唯一 binary 是 `robot-s0`，意图匹配。Part 2 加 `robot-cli` 等工具类 binary 后用自定义 profile 放 unwind 回 CLI（或整体接受 abort，走 CHANGELOG 登记）。

### 3.6 其他

- `JointCommandBuf` 新增（plan 未提，实现时补）：`LatestCommandSlot<T>` 的 T 需要具体类型；`JointCommandView<'a>` 是借用视图，不能直接进 `Arc`。`JointCommandBuf` 是 Copy POD 镜像版，`as_view()` 构造视图。
- `ControlModeRepr` 新增：`ControlMode` enum 没有 `Default` 语义，但 `JointCommandBuf: Default` 需要；用 u8 repr + `Default = Stop`，`From<ControlMode>` 双向转换 + 测试覆盖。

1. **state machine 驱动线程**：state_machine 当前是纯函数 `try_transition`，没有"执行者"。Part 2 谁持有 S0State？候选：
