## 1. A1 E2E 参考模式（clear_estop_e2e.rs）

**预期路径** `crates/robot-tests/src/bin/clear_estop_e2e.rs`

- **双进程启动**：`Args::parse` 接 `--bin-dir` 找二进制 (s0_daemon:539, robot_rpc_gateway:558) → `spawn_daemon` / `spawn_gateway` 用 `tokio::process::Command` 各自起独立进程，stderr/stdout piped + drained到共享 buffer (SubprocessHandle:429,439)

- **关停顺序**：gateway → daemon，各自 SIGTERM + grace 超时 SIGKILL (shutdown_pair:1314) → 都得 ExitStatus::success() 否则返 Err (line 1300-1357)
- **总 case 数**：5 case (selftest + 4 真) + `all` mode 顺序跑 (run_all:1210) → **cargo binary 不塞 cargo test** (line 9, 注释 smoke/e2e 不该默认跑)

## 危险与不确定项

1. **iceoryx2 service 名冲突**：多 case 并发时 robot_id 撞车 → CaseCtx.alloc 用全局 AtomicU32 CASE_SEQ 避免 (clear_estop_e2e.rs:299)；但若 B4 (3/3) 跑多 worker/binary 同时，需确保 robot_id 全局唯一或 cleanup 有 GC 窗口

2. **跨进程同步时序**：daemon RR server started marker 搜索速度 vs 实际日志行刷新 → SubprocessHandle.wait_for_marker 用 50ms 轮询 + 5s 超时 (clear_estop_e2e.rs:456) 足否？真机可能需调

3. **signal handler race**：s1_daemon 用 libc::signal() 全局注册 (s1_daemon.rs:101) → 多进程时 handler 在哪个进程上下文执行？确认 SIGINT/SIGTERM 在正确的 child process

4. **FakeToken vs real TLS**：当前 plain TCP loopback fake token (line 13, robot_rpc_gateway.rs) → B4 (3/3) e2e 限制到 127.0.0.0/8，生产部署必改

5. **Idempotency TTL 边界**：gateway --idempotency-ttl-secs 默认 300 → 若测试 RPC timeout > TTL，retry 时期间项已 GC → 无法 Replay，重新 FreshInsert

6. **Event drain pubsub queueing**：per-ActionId pubsub topic 无持久化 (events_drain/mod.rs:7) → client late subscribe 丢事件；StreamTaskEvents 流中断恢复未定义

7. **Daemon anchor fail-fast**：anchor_or_fail 超时 / stale / joint count 错位 → exit 4，**不** fallback bias=0 (s1_daemon.rs:4-5) → 必须 S0 已运行且 state ready，易在 dev box 碰超时

8. **Wire 源契约**：source_task_id 由 S1 cmd_seq 驱动 (coordinator.rs:667) → 若 B4 task invoke/cancel 之间穿插其他来源的 command，seq 会错位；需验证 B4 task 是否独占 Executing 状态
